# UNA + UltraCode Recursive Improvement Boundary V0.1

**Authorship:** Codex, assisting/build-time co-developer; not UNA-1 or UNA-2.

## Intended architecture

UltraCode may become UNA's local engineering/proposal substrate:

`UNA observes → UltraCode proposes → UNA verifies → shadow benchmark → receipt → Founder gate`

UltraCode is not treated as UNA, a reviewer, an authority, or an implicit source of truth.
Its output is evidence-bearing but untrusted until verified against fixtures and provenance.

## Required properties

- local provider identity and exact executable SHA-256;
- network denied;
- third-party model influence denied unless separately declared and authorized;
- output limited to proposal/evaluation objects;
- no direct code application, route replacement, memory write, model-weight change, connector
  access, external action, or authority expansion;
- recursive learning is session-local until separately reviewed and admitted;
- every proposal carries evidence, uncertainty, provenance, and an action boundary.

The provider boundary is a candidate contract. UltraCode runtime binding is not proven because no
executable, identity, or authenticated receipt was available in the current Brain workspace.
